# Portfolio project quality standard

Every portfolio release must satisfy these rules before publication:

1. Every visible navigation item opens a complete, distinct view.
2. Every button, tab, filter, selector, form, download, and link performs its stated action.
3. Placeholder interactions and decorative controls without behavior are not allowed.
4. Desktop and mobile layouts must be reviewed in a real browser.
5. Type checking and the production build must pass.
6. The deployed URL must return a successful response.
7. The README starts with a current screenshot and places the Live Demo link immediately after it.
8. The repository includes a release report with the screenshot filename, live URL, verification results, and feature inventory.
9. The project tracker and screenshot folder must be updated after successful deployment.
10. Temporary local files must be removed after the online artifacts are verified.
11. A release is not complete until every visible interaction has been exercised in a real browser.
12. Projects must rotate across domains, architectures, and feature sets so the portfolio demonstrates broad senior-level skills rather than repeated dashboard templates.
13. README files must use a polished hierarchy, a current screenshot, a Live link directly below it, concise technology badges, and useful visual markers.
14. Do not activate paid OpenAI API usage or any separate usage-billed generation service. If a workflow requires paid tokens or the included allowance is insufficient, stop before incurring cost.
15. Prefer deterministic templates, local tooling, GitHub Actions, and included product capabilities to control token and service usage.
